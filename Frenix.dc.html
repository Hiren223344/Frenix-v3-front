Frequently asked questions

Does Frenix work with Claude Code and Codex?
Yes. Point Claude Code, Codex, Cline, or any OpenAI- or Anthropic-compatible client at the Frenix endpoint and it works without changes.
Do I need to rewrite my project?
No. Frenix speaks the same request and response formats your client already sends. Swap the base URL and key, keep everything else.
What happens when a provider is down?
Frenix routes around outages automatically. If a model's upstream provider degrades or fails, requests fail over to a healthy provider serving the same model where available.
How much latency does Frenix add?
Under 40ms in the median case. Frenix sits in front of the provider, not behind a queue — it doesn't buffer or batch your requests.
Where do I see my keys and usage?
In the dashboard. Create, rotate, and scope API keys, and see usage broken down by model, key, and time window.
Can I bring my own provider keys?
Yes. Add your own OpenAI, Anthropic, or other provider keys, and Frenix routes through them where allowed instead of shared capacity.

Quickstart

Point your existing client at Frenix by setting two environment variables. No SDK, no code changes.

$ export FRENIX_BASE_URL=https://api.frenix.sh/v1
$ export FRENIX_API_KEY=sk-frx-...

Then call it like you'd call any OpenAI- or Anthropic-compatible endpoint:

$ curl $FRENIX_BASE_URL/chat/completions \
  -H "Authorization: Bearer $FRENIX_API_KEY" \
  -d '{model: "claude-opus-4.5", messages: [...]}'

Rate limits and quotas are counted per request, not per token — usage stays predictable regardless of prompt or output length.
